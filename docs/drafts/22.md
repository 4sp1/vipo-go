# Design decisions: `--debug` flag for `serve` (recorded from a grill session)

Decision record for issue 27 (`docs/issues/27.md`) and the driver-wrapper
follow-up (issue 28). The session walked the design tree in three rounds; this
draft is the shared understanding captured for future reference.

## Problem

`vipo-server serve` currently logs one line via stdlib `log.Printf`
(`cmd/vipo-server/main.go`). There is no way to see what the HTTP layer, the
service layer, or the storage layer are doing. We want a `--debug` capability
to observe every layer, using the stdlib `slog` package.

## Decisions

### Flag surface

- The command takes **both** `--debug` and `--log-level`. `--debug` is sugar
  for `--log-level=debug`.
- `--log-level` accepts `debug|info|warn|error`; flag help enumerates all
  valid values.
- Supplying both flags together **hard-fails**: `serve`'s `RunE` returns an
  error instead of guessing precedence.
- Default level is **`warn`** — set explicitly on the default slog handler;
  by default the server stays quiet.

### Format and plumbing

- Output is `slog.JSONHandler` writing to **stderr**, always. No
  `--log-format` flag (rejected: YAGNI).
- Plumbing is the **smallest possible sub-issue**: cmd configures the global
  slog default; `internal/svc` and `internal/port/state/sqlite` call
  package-level `slog.Debug` with no signature churn. Injected
  (`app.NewServer(dbFile, logger)`) and context-carried logger variants were
  considered and rejected for this sub-issue.
- **Lifecycle messages** (`listening on ...` for serve, `migrations complete`
  for migrate) move from stdlib `log` to `fmt.Println`: level-less, always
  visible, independent of warn-level default. The stdlib `log` import is
  deleted from cmd.

### Logging scope — all three layers

- **HTTP**: one middleware wrapping `srv.Handler` at the top of
  `internal/app/wire.go`. Logs method, path, status, duration. Chosen over
  per-endpoint logging: smallest diff and it also covers 404s/unmatched
  routes. Body logging requires buffering both directions.
- **Service**: explicit `slog.Debug` call sites per operation.
- **Storage**: `slog.Debug` call sites in `internal/port/state/sqlite/port.go`
  for now. A generic `database/sql` driver-level logging wrapper is **out of
  scope** and instead documented in issue 28.

### Level policy (anti-leak split)

Default visibility: only access metadata. **Everything except access
metadata is debug-only**, including error response bodies — the goal is to
prevent leaking content at the default (warn) level. No redaction scheme;
bodies are simply debug-gated.

## Considered and rejected

- **Injected logger** (`app.NewServer(dbFile, logger)` threaded into svc and
  ports): explicit and testable, but signature churn that doesn't fit the
  smallest-sub-issue constraint.
- **Context-carried logger**: same churn plus implicit flow through ctx.
- **Generic SQLite driver wrapper now**: covers migration runner statements
  too, but adds a driver decorator around `glebarez/go-sqlite`; deferred to
  issue 28.
- **`slog.TextHandler`** and / or **stdout**: terminal readability not worth
  losing machine-parsability; stderr is the convention and keeps stdout clean.
- **`--log-level` only** or **`--debug` only**: keys either clunky typing or
  no verbosity escape hatch; both flags with reject-on-combo resolved it.
- **Info default**: would change visible behavior (still arguably fine), warn
  + `fmt.Println` lifecycle lines preserves a quiet default.

## Explicit non-goals (fenced for #27)

- No `--log-format` flag (JSON only).
- No log-file output.
- No per-route log-level control.
- No request-ID / correlation fields.
- No body truncation or size caps.
