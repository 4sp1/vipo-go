# Add `--debug` / `--log-level` to `serve`: observable layers via slog

Sub-issue of [`docs/issues/26.md`](26.md) (#26): to investigate payload semantics from the wire we need to see what actually flows through every layer of the running server. This issue adds a debug capability to `vipo-server` built on the stdlib `slog` package.

Full decision record (including rejected options): `docs/drafts/22.md`.

## Decisions

- **Flags.** `serve` accepts both `--debug` (sugar for `--log-level=debug`) and `--log-level` (string; help lists `debug|info|warn|error`). Giving both is a hard error returned from `RunE`. Default level is `warn`.
- **Format.** `slog.JSONHandler` → stderr, always; no format flag.
- **Plumbing.** Smallest possible sub-issue: cmd sets the global slog default; svc and storage layers call package-level `slog.Debug`. No signature churn into `app.NewServer`, svc, or port constructors.
- **Layers logged:** HTTP (one middleware on `srv.Handler` in `internal/app/wire.go`), service (call sites in `internal/svc`), storage (call sites in `internal/port/state/sqlite/note_store.go` and `event_log.go`).
- **Level policy.** Anti-leak split: only access metadata (method/path/status/duration) is visible above debug; request and response bodies — including error bodies — are debug-only. No redaction scheme.
- **Lifecycle lines.** `listening on ...` and `migrations complete` move to `fmt.Println` (level-less, always visible); stdlib `log` leaves cmd.
- **Driver wrapper deferred.** A generic `database/sql` logging wrapper is documented separately in [`docs/issues/28.md`](28.md) (#28) and is a non-goal here.

## Considered and rejected

See the "Considered and rejected" section of `docs/drafts/22.md` (injected / context-carried logger, immediate driver wrapper, TextHandler, stdout, single-flag shape, info default).

## Explicit non-goals

- No `--log-format` flag (JSON only).
- No log-file output.
- No per-route log level control.
- No request-ID / correlation fields.
- No body truncation or size caps.

## Acceptance criteria

1. `serve --debug` and `serve --log-level=<level>` both work; flag help for `--log-level` enumerates all four levels.
2. Passing both `--debug` and `--log-level` makes `serve` fail with an explanatory error before any server is created.
3. Default output is JSON on stderr at `warn` level; lifecycle lines (`listening on ...`, `migrations complete`) print unconditionally via `fmt.Println`.
4. In debug mode the HTTP middleware logs method, path, status, and duration for every request (including unmatched routes), plus request/response bodies at debug level only.
5. Service and storage layers emit `slog.Debug` diagnostics at their call sites.
6. Above debug level, no request/body content is logged (anti-leak split).
7. All existing tests updated and passing (`go test ./...`); test specifics are left to the implementation plan.
