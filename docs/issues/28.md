# Generic SQLite driver logging wrapper

Split out of [`docs/issues/27.md`](27.md) (`--debug` sub-issue of #26): #27 logs storage activity via hand-placed `slog.Debug` call sites in `internal/port/state/sqlite/port.go`, which covers only the domain-relevant paths. This issue generalizes the mechanism.

## Goal

Implement a `database/sql` driver-level logging decorator that logs every statement (text, args, timings, rows) — including statements issued by anything bypassing the port call sites, such as the migration runner — as `slog.Debug` output.

## Design notes

- Wrap the `glebarez/go-sqlite` driver via `driver.Driver` / `ExecerContext` / `QueryerContext` forwarding, so all `database/sql` consumers get the logging transparently.
- Output stays in the established #27 conventions: `slog.JSONHandler` → stderr, debug level, anti-leak split (parameter values are debug-only data too).

## Considered and rejected (from #27's session)

- Doing it inside #27: rejected to keep the smallest possible sub-issue; hand-placed call sites suffice for the immediate investigation needs.

## Acceptance criteria

1. A driver wrapper logs every SQL statement with timing at debug level.
2. Statements from the migration runner are covered.
3. No observable behavioral change above debug level.
4. Existing tests updated and passing; specifics left to the plan.
